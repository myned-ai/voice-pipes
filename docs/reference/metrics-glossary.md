# Metrics glossary

**Status:** active
**Last verified:** 2026-09-06
**Owner:** Docs

The canonical metric keys you will meet in `turn_metrics`, `metadata.json`,
the admin console and the health verdicts. The normative definitions,
units, budgets and provenance rules are in [VPO metrics](vpo-metrics.md);
this page is the short version.

## Turn snapshot

| Key | Meaning |
|---|---|
| `utterance_id` | Join key for the turn. Spoken turns count up from `1` in every session kind; typed-text turns from `10001`. Capture files use the same number (`001_mic_raw.wav` is the first turn) |
| `total_ms` | Turn start to snapshot, server-measured |
| `interrupted` | Cut short by barge-in |
| `components[]` | Per-component spans in pipeline order, each with `component_id` (`kind:name`), `started_at_ms` / `finished_at_ms` relative to turn start, `latency_ms`, `provider`, `cold_start`, `error`, `extras` |

## Client-reported

Only the client can measure these; they arrive as `timing_report` and
`playback_quality` and are joined to the turn by `utterance_id`.

| Key | Meaning |
|---|---|
| `speech_start`, `speech_end` | The client's own VAD marks |
| `audio_receive` | First response audio byte received |
| `playback_start`, `playback_end` | First sample audible, natural end |
| `e2e_perceived_ms` | `speech_end` to `audio_receive`; the number a user feels. A turn can hold several `speech_end`s, one per pause; the **last one before the reply's first audio** is the anchor. Without a client mark the server's own anchor is the commit time less `endpointing_ms` |
| `underrun_count`, `total_silence_ms`, `gaps[]` | Jitter-buffer underruns in the ideal audio timeline |
| `arrival_wall_ms` | First to last audio frame received; divided by audio duration gives the arrival real-time factor |
| `heard_ms` | Audio actually played before an interruption |

## Health

| Term | Meaning |
|---|---|
| component state | `healthy`, `degraded` (rolling error rate or p99 over budget), `unhealthy` (load or warm-up failure) |
| anomaly | A rule that fired on a turn, keyed `component.rule` (`tts.ttfb_high`, `tts.rtf_high`, `output.emit_rtf_high`, `stt.transcript_empty`, …) with a severity band. Most rules grade speed; `stt.transcript_empty` grades meaning — a turn that committed on a transcript with no words is severe whatever its timings. Plausibility faults (`measurement.zero_with_work`, `measurement.breakdown_exceeds_stage`, `measurement.stages_disagree`, `measurement.missing`, `measurement.audio_inconsistent`) flag contradictory or missing stage telemetry so a 0-with-work measurement is never charged to the next component |
| verdict | The report engine's one-line conclusion naming the culprit stage, or "healthy". It reads `unknown` when a session has no measurements to grade, never "healthy". The headline counts the flags a caller would have felt and names the rest as diagnostic |
| grading rules | The targets and level bands a session is graded by: built-in defaults, then the console's `ADMIN_GRADING_*`, then the pipeline's `[grading]`, then a request's `?targets=`. A grade reached under anything but the defaults says so in its headline and carries `custom_grading` |
| cold start | The first call against a provider handle in a session; excluded from averages by convention |
