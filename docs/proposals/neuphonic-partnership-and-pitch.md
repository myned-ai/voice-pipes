# Neuphonic Partnership Analysis & Outreach Pitch: Introducing Voice Pipes

## 1. Background & Neuphonic Profile

* **Company**: Neuphonic (YC S24 alumni, London / Cambridge UK).
* **Mission**: High-speed, ultra-low-latency on-device Speech Language Models (SLMs) and Text-to-Speech for conversational AI and edge devices.
* **Open Source Assets**:
  * [NeuTTS](https://github.com/neuphonic/neutts): NeuTTS-Air, NeuTTS-Nano, NeuTTS-2E (GGUF, ONNX, PyTorch).
  * [NeuCodec](https://github.com/neuphonic/neutts): 0.8 kbps, 24 kHz neural audio codec.
  * [NeuDecide](https://github.com/neuphonic/neudecide): ~43 MB direct voice-to-action model (Apache 2.0).
  * Official SDKs: `pyneuphonic` (Python), `neuphonic-js` (Node/Browser).

### What Neuphonic Excels At:
1. Groundbreaking lightweight speech models with real-time on-device generation capabilities.
2. Fast single-step neural audio generation (NeuCodec + Qwen2 backbone).
3. Instant 3-second voice cloning without extensive fine-tuning.

### What Neuphonic's Users & Customers Struggle With (The "Ecosystem Gap"):
While Neuphonic produces world-class speech models, **a raw TTS model is not a conversational voice agent**. Developers building real-world conversational products face major orchestration bottlenecks:
1. **The Barge-in Problem**: When a user interrupts an AI voice agent, standard web frameworks buffer several seconds of audio in WebSocket channels or OS audio buffers. Cutting off speech in under 100ms without thread deadlocks or crackling requires specialized pipeline runtime architecture.
2. **Turn-Taking Jitter**: Waiting for arbitrary 1.5s silence timeouts before triggering TTS ruins conversation flow. Pairing TTS with VAD (Voice Activity Detection) and Smart Turn-taking models is essential.
3. **High-Concurrency CPU Contention**: Running 10, 20, or 50 simultaneous CPU voice sessions causes thread-spinning and massive latency spikes unless handled by an asynchronous actor-based runtime with strict session pools.
4. **Multi-Model Pluggability**: Customers often want to mix-and-match local STT (e.g. Parakeet/Whisper), fast LLMs (GGUF/Ollama/OpenAI), and NeuTTS into a single unified WebSocket pipeline.

## 2. Why Voice Pipes is the Ideal Partner for Neuphonic

Voice Pipes is an **ultra-low-latency, modular conversational voice pipeline runtime written in Rust**. It solves every orchestration challenge that sits between Neuphonic's models and enterprise-grade voice agents.

| Capability | Neuphonic Raw Model / SDK | Voice Pipes + NeuTTS |
|---|---|---|
| **End-to-End Latency** | TTS generation only (~100ms) | **Sub-500ms glass-to-glass** (Mic $\rightarrow$ VAD $\rightarrow$ STT $\rightarrow$ LLM $\rightarrow$ NeuTTS $\rightarrow$ Speaker) |
| **Barge-in (Interruption)** | None (must be handled by client app) | **Hardware-level immediate cutoff (< 50ms)** on speech onset |
| **Turn Detection** | Not included | **Silero VAD + Smart Turn v3.2** predictive turn boundaries |
| **CPU Session Scaling** | Basic single-stream Python/C++ | **Bounded `SessionPool` with zero-allocation Rust channels**, thread isolation |
| **Telemetry & Observability** | Basic timers | **`vpo-telemetry` & OpenTelemetry metrics**, per-turn TTFA, RTF/RTFx, audio drift |
| **Edge & Cloud Deployment** | Python package (`pip install`) | **Single compiled static binary or Docker container**, zero Python runtime required |
